실시간 멀티플레이어 체스

채팅 화면 안에서 대국실을 생성하고 다른 사용자와 실시간으로 체스를 플레이하거나 관전할 수 있는 기능입니다.

대국 진행, 관전, 기보, 타이머, 재접속 처리를 WebSocket으로 연결하고, 게임 상태와 결과는 서버가 최종적으로 관리하는 서버 권위(Server-Authoritative) 방식으로 구현했습니다.

서버 권위 기반 게임 상태 관리

체스 게임의 핵심 상태를 클라이언트가 아닌 서버에서 관리하도록 설계했습니다.

클라이언트는 자신의 수를 서버에 요청할 뿐, FEN·SAN·게임 결과 등의 값을 직접 결정하지 않습니다.

서버는 다음과 같은 순서로 게임 상태를 처리합니다.

Client
  │
  │  Move Request
  ▼
WebSocket Server
  │
  ├── 현재 게임 상태 확인
  │
  ├── 플레이어/턴 검증
  │
  ├── 수의 합법성 검증
  │
  ├── 보드 상태 업데이트
  │
  ├── SAN/FEN 및 게임 결과 계산
  │
  └── 전체 참가자에게 상태 전달
  │
  ▼
Clients


클라이언트에서 전달받은 FEN, SAN, 결과값은 신뢰하지 않고 서버가 현재 보드 상태를 기준으로 직접 계산합니다.

따라서 클라이언트에서 임의의 FEN이나 승패 결과를 전달하더라도 서버의 게임 상태 및 전적을 임의로 변경할 수 없도록 구성했습니다.

서버 기준 타이머 동기화

플레이어의 남은 시간은 클라이언트에서 단순히 감소시키는 방식이 아니라 서버가 관리하는 deadline을 기준으로 계산합니다.

Server
  │
  ├── 현재 서버 시각
  ├── 백/흑의 deadline
  │
  ▼
Client
  │
  ├── 서버와 클라이언트의 시간 차이 계산
  │
  └── 서버 시각을 기준으로 남은 시간 표시


클라이언트는 서버와 자신의 시각 차이를 계산하고 서버 기준 시간을 이용해 타이머를 표시합니다.

이를 통해 각 클라이언트의 로컬 시간 차이로 인해 타이머가 서로 다르게 표시되는 문제를 최소화했습니다.

또한 WebSocket 연결이 일시적으로 끊기거나 체스 화면을 닫더라도 서버의 deadline을 기준으로 게임이 계속 진행되도록 구현했습니다.

닉네임 변경 사항

게임 상태가 변경되면 서버가 최신 상태를 참가자들에게 전달합니다.

Player A
   │
   │ Move
   ▼
┌───────────────────┐
│  WebSocket Server │
│                   │
│  Validate Move    │
│  Update Game      │
│  Calculate Result │
└─────────┬─────────┘
          │
     Broadcast
          │
     ┌────┴────┐
     ▼         ▼

이를 통해 여러 사용자가 동일한 게임 상태를 실시간으로 확인할 수 있도록 구성했습니다.

재접속 처리

WebSocket은 네트워크 상태나 브라우저 환경에 따라 일시적으로 연결이 끊어질 수 있기 때문에, 단순히 연결 종료를 게임 종료로 처리하지 않았습니다.

WebSocket Disconnect
        │
        ▼
재접속 유예 상태
        │
   ┌────┴────┐
   │         │
재접속 성공   시간 초과
   │         │
   ▼         ▼
게임 상태    게임 종료
복구


일시적인 연결 끊김이나 브라우저 새로고침이 발생하더라도 일정 시간 동안 재접속을 허용합니다.

재접속에 성공하면 기존 대국방과 플레이어의 진영을 복구하고 게임을 이어갈 수 있도록 구현했습니다.

기보 및 복기

대국 중 발생한 수를 기보로 관리하며, 사용자는 특정 수를 클릭하여 이전 게임 상태를 확인할 수 있습니다.

1. e4      e5
2. Nf3     Nc6
3. Bb5     a6
4. Ba4     Nf6


복기 상태에서는 이전 수를 확인할 수 있으며, 최신 수로 돌아오면 다시 현재 게임 상태를 확인할 수 있습니다.

게임이 종료되면 결과를 SQLite에 저장합니다.

Draw
Loss

기술적으로 고려한 부분
1. 클라이언트를 신뢰하지 않는 게임 상태 관리

클라이언트가 게임 결과나 보드 상태를 직접 결정할 수 있도록 하면 조작 가능성이 발생합니다.

이를 방지하기 위해 서버가 실제 게임 상태를 보유하고, 클라이언트의 요청을 검증한 후 상태를 변경하도록 설계했습니다.

2. 로컬 시간이 아닌 서버 시간 기준 타이머

각 클라이언트의 시스템 시간이 서로 다를 수 있기 때문에 클라이언트의 로컬 시간을 기준으로 타이머를 계산하지 않았습니다.

서버의 deadline을 기준으로 남은 시간을 계산하여 플레이어 간 타이머 차이를 최소화했습니다.

3. WebSocket 연결 단절과 게임 상태 분리

네트워크 연결이 끊어졌다는 이유만으로 게임 상태를 삭제하지 않도록 했습니다.

게임 상태와 WebSocket 연결 상태를 분리하여 일시적인 연결 단절 이후에도 기존 게임을 복구할 수 있도록 구성했습니다.

실행

프로젝트 폴더에서 최초 실행합니다.

uv sync --locked
uv run --locked python run.py


서버가 시작되면 표시된 LAN 주소로 접속한 후 체스 버튼을 눌러 대국실에 입장할 수 있습니다.

테스트

체스 기능에 대한 테스트를 실행합니다.

uv run --locked python -m pytest tests/test_chess_manager.py -q
